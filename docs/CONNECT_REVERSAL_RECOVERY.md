# Connect 冲回队列与人工核对

撤销核销或整单退款会在同一数据库事务内写入 `pending_reversal` 和 `reversal_queued`，事务提交后才允许调用 Stripe。`connect-transfers` 定时任务和商家流水重试接口都可处理这个明确的待发送状态。若调度器停用，队列会保留；恢复调度器或对待发送的具体流水调用现有重试接口即可继续。未发出的转账仍在本地直接取消。

派发前系统提交 `reversal_dispatch_started`，然后携带固定的 `reversal-{流水 ID}` 幂等键请求 Stripe。正常返回且数据库提交成功后，流水成为 `reversed` 并保存 Stripe 冲回编号。超时或异常会标记 `reversal_result_unknown` 并通知管理员；进程中断或 Stripe 成功后本地提交失败可能保留 `reversal_dispatch_started`，调度器发现该状态超过 15 分钟会通知管理员。这两种状态、以及旧版遗留的其他待冲回状态，都不能自动重发，重试接口返回 409。同一券的重新核销保持阻止，直到上笔转账/冲回被确认处理。

管理员可通过 `/api/v3/admin/connect/recoveries` 查看待冲回流水及 `note`。财务人员应使用流水的转账编号、金额和请求幂等键在 Stripe 核对是否已经冲回，并保留可追溯凭证，再按公司经批准的对账流程修复记录；未核实前不要清除标记或重复发起冲回。当前系统没有针对不确定结果的自动确认接口，不能声称已经自动完成恢复。
