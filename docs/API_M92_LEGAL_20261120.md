# M9-2 服務條款與私隱政策 API
狀態：開發交接，尚未部署。此分支不知道實際法律文本或上線日期，沒有填入臨時的正式同意紀錄。所有路徑以 `/api/v3` 為前綴；此頁的域名及版本只用於說明。

## 上線前設定
法務確認並發佈不可變的版本網址，再在所有 API 實例同步設定 `LEGAL_TERMS_VERSION`、`LEGAL_TERMS_URL`、`LEGAL_PRIVACY_VERSION`、`LEGAL_PRIVACY_URL`。網址限 HTTPS，不得用測試或示例網址；更新文件內容時必須同時更新版本號，不能以同版本換網址或內容。套用 Alembic `0020_m92_legal_consents`。先驗證所有已發佈網址可公開讀取；API 只驗格式，不在每次請求抓取網頁。

設定不全時，套餐、公開目錄和匿名瀏覽按原權限運作；註冊、登錄、政策查詢和需要完整會話的路徑返回 503 `legal_documents_unavailable`。只有 dev 全部未設才不強制同意，且查詢返回 `{"required":false,"documents":{}}`。登出和刪帳不需要先接受新條款。環境預設 production；未驗證的社交登入 stub 只可在 dev 使用。

## HTTP 契約

### GET /legal/current （公開）
200 範例：
```json
{"required":true,"documents":{"terms":{"version":"2026-11-20","url":"https://legal.example.test/terms/2026-11-20"},"privacy":{"version":"2026-11-20","url":"https://legal.example.test/privacy/2026-11-20"}}}
```
生產環境若未配置兩份正式文件，返回 503，客戶端不可顯示空連結或假同意。

### POST /new-register 及 POST /new-register-vendor（公開）
沿用現有欄位，增加頂層 `accepted_terms_version` 和 `accepted_privacy_version`。勾選同意及讀取當前版本後才帶入。商戶仍用同一組欄位。
```json
{"email":"customer@example.com","password":"example-password","name":"陳小明","phone":"","role":"customer","accepted_terms_version":"2026-11-20","accepted_privacy_version":"2026-11-20"}
```
200 沿用驗證碼提示。不提供或版本過時返回 400 `detail.code=legal_versions_changed` 和 `detail.documents`，不註冊、不生成 OTP。前端要重新顯示政策並清掉勾選，不可自動接受。

### POST /new-verify-otp 及 POST /password/verify-otp（公開）
原欄位不變。如果文件在註冊和 OTP 驗證之間更新且沒再次同意，返回 409 `legal_versions_changed`；原 OTP 尚可於有效期內繼續使用。重新取得客戶確認後，在同一 OTP 請求加上上述兩個版本欄位：
```json
{"email":"customer@example.com","code":"123456","purpose":"register","accepted_terms_version":"2026-11-21","accepted_privacy_version":"2026-11-20"}
```
成功返回與登錄相同的 token 契約。忘記密碼 OTP 即使成功，若尚未同意，也只返回受限 token。

### POST /login、GET /me、POST /legal/accept
登錄成功，沿用現有 `access_token`、`token_type`、`user_id`、`role`、`email`，另含 `consent_required`、`legal_documents`。若為 true，token 最長 15 分鐘，僅可用於個人會話狀態、接受文件、登出或刪帳，不可存取受保護業務；公開接口視為訪客，不顯示個人化結果。恢復舊 session 也要呼叫 `GET /me`；若需要新同意，該接口只返回 `id`、`role`、`consent_required: true`、`legal_documents`，暫不返回個人資料。正常會話仍按原資料返回其餘資料。

經客戶確認兩份文件後，以現有 Bearer token 提交：
```http
POST /api/v3/legal/accept
Authorization: Bearer <token>
Content-Type: application/json

{"accepted_terms_version":"2026-11-21","accepted_privacy_version":"2026-11-20"}
```
200 返回新的正規 token、`consent_required:false` 及 `legal_documents`。客戶端須覆蓋受限 token。無 token 或帳戶已停用返回 401；內容過時返回 400；相同版本與網址組合重複提交不新增紀錄。受保護接口遇未同意舊會話返回 428 `legal_consent_required`；已重新同意但仍拿舊受限 token 呼叫的客戶端返回 403 `legal_consent_token_scope`。

記錄以用户 ID、兩份版本、當時網址、UTC 時間為準。不記錄 IP 或裝置資訊。沒有為歷史用戶僞造同意。歷史保留策略與 M9-7（包括去識別化）須由負責人協調。
