## M6【P0】结算与对账口径修正（审计新发现）
位置：`apps/api/app/routers/admin_v2.py` 的 `generate_settlement`（约 255–285 行）、`run_reconciliation`（约 491–560 行）、`_face_value`（约 90 行）
问题
1. 结算和对账查核销时没有排除已撤销的核销（`revoked_at` 不为空），商户会被结算已撤销的单；撤销发生在结算单生成之后时，对账也不会报差异。
2. 结算金额取券面值 `cash_amount → discount_price → regular_price`，不是实付额。免费券按 `regular_price` 结算，等于平台替商户买单；套餐订单应取 `Order.paid_amount`，已退款订单不应结算。
要求
1. 结算与对账都排除 `revoked_at` 不为空的核销；对账新增差异类型 `revoked_but_settled`（结算单里有明细、核销已撤销）。
2. 结算基数改为实付额：套餐券取订单实付，价格券取 `discount_price`，免费券和纯门槛券为 0 不进结算（若产品决定平台为免费券补贴商户，需由我确认后另做，不要默认）。已退款订单排除。
3. 对账的 `expected` 与结算用同一个函数，避免两处各算各的。
4. 同步更新测试：撤销核销不进结算；免费券结算为 0；已退款套餐不结算；撤销后重跑对账出现 `revoked_but_settled`。

## M7【P1】评价星级口径修正（审计新发现）
