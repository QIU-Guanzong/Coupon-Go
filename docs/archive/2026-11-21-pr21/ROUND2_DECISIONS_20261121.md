## 二、给 dot

1. **接手 #13**：把 `codex/pr13-deletion-safeguards-20261121` 基于最新 main rebase（迁移号保持 0021），开新 PR，PR 说明里写明取代旧 #13。
2. **修死胡同（必须）**：现在只要有「待确认返现 / 追踪中返现」就 409，而返现已默认关闭、待确认的永远不会解锁，用户将永远删不掉帐户，过不了 App Store。改为：
   - 待确认、追踪中的返现**不阻止**删号；删号时作废并写账本（reason `account_delete`），保留记录；
   - 有**可提现**余额：409，提示先提现（muse 会放开关闭状态下的提现，见下）；
   - 有处理中的提现：409；
   - 其它拒绝条件保留。每个拒绝条件的提示语都要说明用户下一步怎么做，不要只写「請聯絡平台」。
3. **未使用的付费券阻止删号**这一条保留，但 App 里必须有退款入口，前端对应文案写「請先退款或使用」。
4. 测试补：待确认返现可删号；可提现余额被拒；复活攻击失败；同邮箱重新注册得到全新帐户。附 PostgreSQL 并发记录（删号 vs 重置密码、删号 vs 下单）。
5. **测试隔离**：按裁决 3 单独开 PR。
6. **文案**：`main` 里 `5864f1c` 重新加入了「下載 Android 示範版 / Download Android demo」和「暫未開放」，违反「界面不出现示范、demo、尚未开放」。改回「下載 Android 版」，横幅改为「以下商戶及優惠為範例資料，僅供瀏覽。」，走 PR。

## 三、给 muse

1. **#13 停手**，不再修改。
2. **#16 剩一处（合并前必须改）**：`request_payout` 现在把提款请求超时当成「失败」并释放余额，但 Stripe 可能已执行。改为：
   - 网络超时、连接错误、5xx：**保持 `processing`**，用同一个幂等键（`payout-{entry_id}`）由调度器重试确认，不释放余额；
   - 只有 Stripe 明确拒绝（4xx）才标 `failed` 并释放余额；
   - 同样检查转帐、冲回路径对「结果未知」的处理一致；
   - 测试：模拟「超时但 Stripe 已执行」，重试后只有一笔，余额始终不被重复释放。
   - 附 PostgreSQL 并发测试日志：同一商户两个并发提款，总额超过余额时必须有一个被拒。
3. **M10（已合并）的一处修正**：关闭返现时不要拦截提现。只停止新增返现，已有的可提现余额仍允许提现（否则用户被冻结资金，也和删号流程互相卡死）。改 `POST /cashback/withdraw`，补测试，开 PR。
4. **安全基线分支**（`stage0/security-baseline-20261121`）：看起来符合要求，请开 PR。补一条：在 PR 说明里写明 `FORWARDED_ALLOW_IPS` 部署要求，因为限流按 IP 取地址。
5. 队列顺序更新：测试隔离 PR → 安全基线 → #12 → #14 → #18 → #20 → #11 → #16 → #19 → #15 → #17。#13 由 dot 负责，按其完成时间插入 #12 之前。
